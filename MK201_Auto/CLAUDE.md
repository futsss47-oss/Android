# MK201 Auto — память для Claude

Программа стенда (Python 3 + Tkinter, Windows): прошивка, калибровка AI/AO, проверка DO→DI, CI, Ethernet и RS-485
контроллера MK201 («Нефтеавтоматика»), протокол Excel. Пользователь — инженер стенда, пишет по-русски; отвечать
по-русски, коротко, без жаргона. История изменений и описание работы — в `README.md` (раздел «Версии» вверху).

## Железо стенда
- Плата MK201: Service Port = USB-COM FT232 (VID 0x0403), 115200 8N1, адрес 1. **У каждой новой платы новый COM** —
  программа сама ищет плату при СТАРТе (`ensure_board_port`, `ports.find_board`: сначала FTDI, MOXA пропускает).
- **MOXA UPort (VID 0x110A), два порта:** один — калибратор Yokogawa CA71 (RS-232, 9600 8N2), другой — RS-485 к плате
  (режим RS-485 2W в драйвере). Плату на портах MOXA не искать никогда (через RS-485 она тоже ответит).
- Блок реле ESP32 (CH340/CP210x, «ID?» -> MK201-RELAY), сканер штрихкодов VID 0x27DD.
- VISA: блок питания АКИП-1168 (CH1 = питание платы 24 В, CH2 = DO→DI), второй экземпляр отвечает «DPS3…»;
  генератор АКИП-3409/2 (Siglent SDG).
- Ethernet платы: IP по умолчанию **10.155.26.140**, Modbus TCP порт 502. ПК должен быть в подсети 10.155.26.x.
- 03.11.2026: RS-485 у пользователя заработал (была переполюсовка A/B). Шаг «Порты 1–3» пишет 19200 8N1 адрес 1
  (из настроек RTU); подбор скорости из настроек платы в проверке RS-485 оставить — пользователь просил.
- На ПК пользователя есть com0com (COM20/COM21) — автопоиск их пропускает (`is_virtual`), Bluetooth тоже.
- Порт RS-485 платы отвечает только в режиме MbSlave (регистры 1010+8+6·p: адрес, режим, мастер, код скорости,
  чётность, стоп). MOXA пользователя — UPort 1150, COM44, режим RS-485 2W выставлен в свойствах адаптера.
- RS-485 «по умолчанию модуля» (как в конфигураторе): 19200 8N1, адрес 1. Три клеммы: XP10 (порт 1), XP9 конт. 1–5
  (порт 2), XP9 конт. 6–10 (порт 3).

- CI (1.33): на клемме — счётчик на всех точках, потом частотомер (`ci_freq_all`), потом другая клемма. Форма по
  точкам из настроек `ci_wave_1..3`: 10 Гц прямоугольник, 15 и 30 кГц синус (пользователь: прямоугольнику на 15/30 кГц
  не хватает амплитуды). Генератор: `set_wave`, форма пакета — `C1:BTWV CARR,WVTP,…`, непрерывно — `BSWV WVTP`.
- Пользователь спрашивал протокол без шаблона Excel и частотомер в протоколе — не сделано, нужен файл шаблона.

- Протокол (1.34): шаблона Excel больше нет. `protocol_xlsx.Protocol` — модель (словарь, кладётся в .json как
  `protocol_data`) + рисование xlsx заново при каждом сохранении: A4, 13 колонок, Arial 9, разрыв страницы после
  раздела 3, масштаб считается по высоте строк; проверять вёрстку через `soffice --convert-to pdf` и `pdfinfo`.
  Таблица 6.5 — частотомер (пользователь просил свой номер таблицы). Тот же день и номер — дописывается, иначе новый файл.
- 1.37: при `conn_mode` = Modbus RTU / TCP Service Port не трогать нигде: автопоиск `board=False`, ожидание после CH1 —
  ответ по выбранной связи, `svc_port` в сценарий пустой, `step_finish` по основной связи (по RTU обрыв после Off — норма).
- Частотомер: допуск ±0,01 % ОТ ЗАДАННОЙ частоты (паспорт «основная относительная погрешность»; PDF пользователя
  421457.190 РЭ), не от 30 кГц — пользователь поправил. 10 Гц → ±0,001 Гц; на стенде 10 Гц самый напряжённый.
- Журнал MAC (`mk201_macbook.py`): книга Excel на сетевом диске, лист `0016D6_1`, столбец A — MAC, D — серийный
  (`s/n: 1002011002600085`, регистр и пробелы разные, формулы с кэшем). Ищем по ПОЛНОМУ номеру изделия (последние 7 цифр
  у разных изделий совпадают). Читается копия, индекс в `mk201_mac_cache.json`. В журнал ничего не пишем. Нет номера —
  предупреждение и ручной ввод.
- Шаг `finish` (последний): через Service Port счётчики CI = 0, DO выключены, порты 1–3 Off. RS-485: после чтения на
  клемме связь держится `rtu_hold` = 3 с. Подсказок по контактам XP9/XP10 в окнах нет (просили убрать).
- В «Проверке» вручную только CAN; Ethernet, RS-485_1–3, Service USB в таблице 7 ставит проверка.

## Протокол платы (подтверждено)
- Все регистры читаются/пишутся «Settings»-функциями: ЗАПИСЬ = 100, ЧТЕНИЕ = 101. 32-битные и float — МЛАДШЕЕ слово
  первым. Карта регистров — `mk201_proto.py`, расшифровка кадров — `modbus_decode.py`.
- Оригинальный конфигуратор `configurator_MKLogic200_3.4.4.exe` — Python 3.7 + pymodbus + `pymodbus_ext`, упакован
  PyInstaller (распаковка pyinstxtractor-ng, декомпиляция decompyle3). Три способа связи с ОДИНАКОВЫМИ командами:
  Service Port (RTU 115200, id 1), Modbus RTU (RS-485), Modbus TCP (порт 502, MBAP). Таймаут 1 с.
- Дата/время (1.39, пользователь: «как в оригинальной программе, никаких запасных вариантов»): одна запись 1042 ×6
  (час, мин, сек, год−2000, мес, день, функция 100) в начале секунды, через 1 с чтение 1036 ×6 и сравнение как
  `cmp_with_system_datetime` конфигуратора: даты равны, |время| ≤ 1 с. Без ключа, повторов и других порядков полей.
- Пауза между шагами прогона `step_pause` = 1 с (пользователь просил).
- Серийный 1102 (u32) и MAC 1104 ×3 пишутся после ключа разблокировки 1100.

## Устройство кода
- `mk201_proto.py`: класс `MK201` (RTU по COM или `host=` -> `TcpStream`, Modbus TCP под видом последовательного порта —
  весь разбор кадров общий). `reopen()`.
- `mk201_auto.py`: окно (вкладки Подключение / Проверка / Журнал / Ручной режим), подключение приборов, прогон.
  «Связь с платой»: `conn_mode` = Service Port / Modbus RTU / Modbus TCP; `board_link()`, `_board()`, `test_link()`.
- `mk201_workflow.py`: `Runner` — шаги прогона (TABLE). Шаги «eth» и «rs485» идут после CI: эталон через Service Port,
  отключение, чтение серийного/MAC/времени по TCP и по RTU на 3 клеммах (окно «переключите клемму»), сверка, обратно.
- «Повторить непройденные»: прошедшие шаги и ✔ в таблицах остаются; AI/AO перемеряют только каналы вне допуска
  (годные — из .json прошлого прогона этого номера за сегодня).
- `build_exe.bat` (кодировка CP866, CRLF!): сборка `--onedir` в папку `MK201_Auto_app` (однофайловый exe падал без
  админа: «Could not create temporary directory»), версия вшивается `--version-file`. Правя батник — читать/писать
  в cp866, кодировать ДО открытия файла на запись; символы «…», ««»» в cp866 нет.
- Exe запускается только из `MK201_Auto_app` рядом с `_internal`; батник делает ярлык на рабочем столе (PowerShell
  WScript.Shell). Ошибка «Failed to load Python DLL …\_internal\python312.dll» = exe скопировали отдельно.
